## Small talk

Recruiters skim. Engineers click.  
Your GitHub needs a **sharp story**, not 40 half repos.

---

## Pin your best 2–3

For each project README:

1. Problem in 2 lines  
2. Demo GIF / screenshots  
3. Architecture diagram  
4. Tech stack  
5. What you measured (metrics!)  
6. Tradeoffs you made  
7. One "next improvement"  

---

## Profile README blurb (template)

```markdown
## Hi — I build AI features that ship
- RAG / LLM apps with eval + APIs
- Classical ML when tabular is enough
- Python · PyTorch · HF · FastAPI · Docker

Featured: [DocuBuddy](link) — grounded Q&A over private docs
```

---

## LinkedIn / resume bullets (formula)

**Verb + system + metric + constraint**

> Built a RAG API over 200 internal docs with citation UI; cut hallucinated answers on golden set from 40% → 12%; p95 latency < 3s on CPU retrieval + hosted LLM.

---

## Talking your project in interviews (STAR-ish)

- **Situation**: people couldn't find answers in docs  
- **Task**: grounded Q&A  
- **Action**: chunking, hybrid retrieval, prompt, eval harness  
- **Result**: numbers + what you'd do next  

Practice out loud once. Seriously.
